# Compiler-owned UI journey prototype

This isolated opt-in experiment compiles visible interaction checks from the validated flat-collection contract while preserving model-written JSX and CSS. It is a functional reference for the next experiment, not a new default design or a claim of winning quality.

`compileProductSpec(spec, { executableCollection: true, compiledUiJourneys: true })` selects `verification.collection-ui`. That block owns the test source and semantic binding helper. Only `src/product/App.tsx` and `src/product/styles.css` remain model-owned. The runtime flag, interpreter prompts, builder prompts and judging semantics are unchanged.

The product spreads `collectionUi(controller)` bindings onto its own create, record, edit, remove, action and field elements. It controls their markup, positioning, classes and accessible names. The helper supplies handlers and stable attributes; it does not supply pages, layouts or CSS. `collectionValue` provides the predictable displayed representation of fields. `ProductEditor` remains the existing protected form/controller seam.

Tests render the actual product App, interact with visible named controls, fill labeled form fields, inspect displayed values, and unmount/remount to test reloading. They do not seed raw storage or inspect a private persistence envelope. They exercise create/edit/delete, required editable fields, every reachable canonical workflow edge, unavailable actions, persistence after mutations, and a storage-write failure. Test cases contain compiler-fixed inputs and expected states; UI repairs cannot rewrite them. The canonical workflow guards determine reachability, and inability to synthesize a reachable valid sample fails compilation instead of producing vacuous tests.

Local evidence: both public development fixtures passed in independent list and table reference compositions (book: seven checks; SaaS: eight). The same unchanged tests failed four deliberately broken App variants: inert action controls, removed persistence, hidden record values, and a missing create control. Materialized app typechecks and the harness typecheck passed. No provider calls were made. The reference source is deliberately plain and lives only in tests.

## Scope and remaining metadata

This prototype deliberately does not tag a prose acceptance journey as covered. The existing journey gate still returns failed for those untagged journeys. A full production integration needs an explicit machine-readable mapping from atomic canonical obligations to interaction checks; matching a journey ID alone would overclaim. Independent evaluation against the original prompt remains necessary.

The existing contract determines field requirements, enums, defaults, state guards, action inputs/assignments, canonical transition edges, and local persistence. It does not identify which CRUD operations the user actually requested, whether details should live in another route/dialog, which values should be shown in summaries, what filters/counts are required, or how hidden enum values should be named for people. Currently enabling this prototype deliberately asks the UI to expose the controller's CRUD surface and all field values on the collection view; this is too narrow to make it a universal UI contract. No multi-entity, transaction, external integration, advanced validation, search/filter/count, responsive layout or visual-quality coverage is claimed. The current single-record scenarios do not establish record-isolation behavior between multiple records.

The useful next step is to retain the compiler-owned test seam and add only the interaction metadata needed for the supported product scope: explicit create/edit/delete capabilities, detail navigation/value display bindings, filter/count obligations, and atomic journey-to-check mapping. This would remove speculative generated test code and its repair loops while allowing distinctly composed products. It should remain opt-in until those coverage semantics and fresh model-produced outputs are validated. There is no measured provider token or cost saving yet; only the test-source ownership reduction is demonstrated.
