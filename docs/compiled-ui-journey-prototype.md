# Compiler-owned UI journey experiment

Enable `CHALLENGE_EXECUTABLE_COLLECTION=1 CHALLENGE_COMPILED_UI_JOURNEYS=1` to try this path. It applies only when the accepted specification selects a supported compiled collection. Custom products and the default path retain their existing test generation. This is an opt-in candidate, not evidence of improved fresh generation until the independent comparison runs.

The builder writes three files: `App.tsx`, `styles.css`, and `interaction-manifest.json`. It owns JSX, CSS, product identity and composition. The compiler owns domain behavior, persistence, semantic binding helpers, and executable test source. Bindings supply attributes and handlers, not pages or styles. Values can appear in summaries or a named details view; create/edit/action forms use the protected ProductEditor. Test-only list, table and details reference compositions demonstrate the seam and are never selected as generated product designs.

The typed manifest declares explicit programs corresponding to canonical journeys. Operators cover create, edit, valid workflow actions, removal, visible field assertions, refresh, filters, counters, invalid creation and rejected storage writes. Expected states and counts are computed from the accepted deterministic domain contract. The tests interact with the actual App through visible, named controls and labeled fields; they neither seed nor decode the private storage envelope. A failed-save check proves a canonical save was attempted, a visible error appeared, and prior visible and persisted records remain intact.

A journey ID alone creates no passing evidence. Each supported program must perform interactions and outcome assertions. Mutations must be asserted before the next mutation; collectively fully supported programs exercise canonical actions, inspect record fields, establish persistence, distinguish filter inclusion/exclusion, and observe counters at different derived values. Every declared filter must independently change membership. Free-text value substitution and indistinguishable enum display labels are rejected. Explicitly unsupported journeys produce no passing tags and remain uncovered. These checks establish only the operations and assertions actually executed: the unchanged external evaluator still assesses fidelity to the original prompt.

The first valid manifest is frozen. Subsequent UI repairs may change only App/CSS; they cannot replace the manifest, compiled tests or display rules. Invalid manifests receive an actionable compilation failure and can be repaired before freezing. Every verification attempt retains a coverage sidecar with executable steps, expected outcomes, manifest hash and unsupported cases. Existing journey reconciliation consumes the named executed tests, and normal build/quality gates remain in place.

## Local evidence

Public development Book and SaaS fixtures execute the same protected tests in list, table and details compositions. Independent journeys remain isolated by the materialized verification setup. Unchanged tests reject deliberately broken App variants with inert actions, lost persistence, directly or indirectly hidden values, missing create controls, ignored filters and constant counters. Invalid, vacuous or contradictory manifests and attempts to weaken a frozen manifest are rejected. Materialized app and harness typechecks pass. No paid provider calls were used to establish this local evidence.

This proves the compiler/testing seam, not improved model interpretation, visual quality or token savings. Fresh model-produced applications, independent raw-prompt journeys, retained failures and whole-run resource costs decide adoption. It supports the flat-collection contract, not arbitrary multi-entity transactions or external integrations. Record controls must be in each record's bound summary, while fields may be in details. The active editor is the named ProductEditor form. Reload explicitly resets filters through visible controls; it does not require filter preferences to persist. More elaborate navigation and unsupported operations must remain explicit rather than being counted as covered.
